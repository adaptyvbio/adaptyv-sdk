Adaptyv SDK ↔ Foundry API alignment

Where the published adaptyv-sdk diverges from the deployed Foundry API, and what to change

2026-06-03 · SDK adaptyv-sdk v0.1.0 at commit 5e3b678 · deployed spec Foundry API info.version 0.0.2 · API docs

Recommendation

Regenerate the SDK's typed layer against the current spec and repair the hand-written HTTP layer to match it. The committed generated.py was produced on 2026-01-06 from …/openapi.json, a URL that now returns 404 because the spec moved under /api/v1. The contract has since drifted in 73 verified places. Of these, 17 break real calls today: three endpoints point at paths the server no longer exposes, three list endpoints deserialize into models whose required keys never arrive, and two enums reject values the live API returns.

Regenerating the models fixes most schema, enum, and missing-model gaps in one step. It does not fix the hand-written pieces — wrong path literals, missing endpoint wrappers, and stale pagination parameters in foundry.py — which need the edits listed under Remediation. None of the 73 findings requires a server change; the deployed API is the reference, and the SDK is what trails it.

How this was checked

The deployed spec was fetched live from https://foundry-api-public.adaptyvbio.com/api/v1/openapi.json (30 paths, 71 component schemas) and treated as the source of truth.The SDK client's base URL already includes /api/v1 (config.py:14), so a spec path /api/v1/experiments corresponds to an SDK call of /experiments. Paths were normalised on that basis before comparison. An independent agent compared each of nine resource groups, plus the enum and shared-schema surface and the codegen pipeline; a separate agent then took each candidate divergence and tried to refute it by re-reading both sides. Only divergences that survived this adversarial verification appear below. A first pass left 16 candidates unresolved through transient agent errors; a second pass re-verified them, and direct inspection of the spec and source confirmed the final thirteen (enums and custom-target models). Three candidates were checked and dismissed.
