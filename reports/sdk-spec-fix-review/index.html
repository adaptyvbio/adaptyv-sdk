For the reviewer

This branch realigns the SDK with the live API and repairs the codegen pipeline that let it drift. The work began from a verified divergence report of 73 findings (17 breaking real calls). Every finding traces to one root cause: the committed generated.py was built from a codegen URL that now 404s because the spec moved under /api/v1.

The change is six focused commits, each independently coherent, and the gate (mise run check) is green. To act on this branch, weigh the four key decisions and the breaking changes, then answer the four open questions — the calls I could not settle alone. Approve if those decisions stand and the breaks are acceptable downstream.

Why this change

The deployed spec (live, 30 paths, 71 schemas) had moved ahead of the SDK in 73 verified places. The headline breaks: a request to /experiments/costestimate (the real path is cost-estimate); confirm() posting to a nonexistent /confirm; list models that could not parse the live items envelope; and two enums that rejected values the API returns. Whole resources — quotes, tokens, feedback, custom targets, health — had no SDK surface at all. The divergence report holds the full per-finding analysis with adversarial verification.

Key decisions

Four judgement calls shaped the branch. Each states what it rejected, so the work is auditable.

Hybrid type layer — regenerated component models + hand-maintained list envelopes

Why The deployed spec defines list responses as anonymous inline objects, so codegen cannot emit named SequenceList/TargetList models the code relies on.

Chosen Keep generated.py codegen-owned for all named components and enums; add types/lists.py with a generic Paginated[T] and per-endpoint item models.

Rejected Raw codegen output (drops the list models, emits Type1–Type7); or hand-editing generated.py (not reproducible via gen:types).

uuid / date-time → str — kept the SDK's string-based public surface

Why Codegen maps format: uuid/date-time to UUID/datetime, which would change the SDK's public return types and ripple through every call site.

Chosen Map both formats to str via --type-mappings. The JSON wire type is still a string; the format is only a refinement, and the prior SDK was string-based.

Rejected Embrace UUID/datetime objects in the public models (richer, but a breaking surface change and far more churn).

Python floor 3.11 — raised the minimum from 3.10

Why Requested. Also lets generated enums use StrEnum (a clean str subclass) rather than plain Enum.

Chosen Bump requires-python, ruff/mypy targets, and the codegen target to 3.11.

Rejected Stay on 3.10 with plain Enum + model_dump(mode="json") (kept regardless, and still correct).

Enable pydantic mypy plugin — so strict mypy understands Field() defaults

Why Under strict = true without the plugin, mypy treats every x = Field(default) field as required and raises false call-arg errors.

Chosen Add plugins = ["pydantic.mypy"]; the plugin ships with pydantic.

Rejected Sprinkle redundant kwargs or # type: ignore at every model construction (noisy, fragile).

Breaking changes

The repo convention is loud, breaking changes over compatibility shims. The user-visible breaks:

  • experiments.confirm() is removed. Use submit() to advance an experiment and confirm_quote() to accept its quote.
  • experiments.update_priority() is removed. Use modify() (HTTP PATCH), which carries the full ModifyExpRequest.
  • experiments.create() no longer accepts experiment_id; the deployed CreateExpRequest dropped that field.
  • List methods now return typed Paginated[T] envelopes — iterate .items (was .sequences/.targets/…).
  • Minimum Python is now 3.11 (was 3.10).
